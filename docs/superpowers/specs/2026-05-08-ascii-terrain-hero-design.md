# ASCII Terrain Hero — Design Spec

## Overview

Replace the current "chromatic drift" ASCII hero with a **dense ASCII terrain renderer**. Every cell on the screen is filled with a character from a density ramp, chosen by procedural terrain elevation. The name **WORTHY RAE** is revealed by rendering those cells in bold white. Duotone color palettes cycle through curated pairs over time.

## Core Concept

A full-screen canvas where:
- Every cell contains an ASCII character (no gaps)
- Character chosen by **visual density** based on terrain elevation: `. , ' : ; | ! i l c / 1 { [ ? e o a s d 0 O k x X d p b W M # @`
- Terrain generated by **domain-warped fractal noise** with **ridged noise** for dramatic peaks/valleys
- Character brightness scales with elevation (dark valleys → bright peaks) for 3D depth
- Colors come from **duotone palettes** that crossfade between 5 curated pairs
- Name mask generated via offscreen canvas text rendering for clean, large letterforms

## Terrain Engine

### Noise

- **Perlin noise** base with custom permutation table
- **FBM** (fractal Brownian motion): 6 octaves, persistence 0.48, lacunarity 2.05
- **Ridged noise**: 5 octaves with absolute-value inversion and sharpening (`n = (1-|n|)²`)
- **Domain warping**: two layers of warp — noise fed back into coordinates for organic flowing features
- Final terrain: `fbm * 0.6 + ridged * 0.8`

### Animation

- **Cyclical time**: `sin/cos` based offsets (not linear drift) so terrain never settles into dead zones
- Time feeds into domain warp coordinates, creating continuous morphing
- Multiple frequency ratios (0.07, 0.09, 0.11, 0.13, 0.14, 0.17) prevent visible looping

### Contrast

- **S-curve** (logistic, strength 8) applied to normalized elevation to spread values across the full character ramp
- Ensures both light characters (`. ,`) and dense characters (`# @ W`) appear frequently

## Color System

### Duotone Palettes

5 curated pairs, each with two complementary colors and a background:

| Name | Color A | Color B | Background |
|------|---------|---------|------------|
| Prestige | Emerald `(80,255,180)` | Gold `(255,240,100)` | Dark forest |
| Reef | Electric blue `(100,180,255)` | Coral `(255,160,140)` | Deep space |
| Dusk | Violet `(200,120,255)` | Amber `(255,220,90)` | Dark purple |
| Frost | Ice blue `(160,235,255)` | Rose `(255,180,210)` | Slate |
| Neon | Lime `(180,255,100)` | Hot pink `(255,100,190)` | Dark green |

### Color Blending

- **HSL interpolation** for A→B gradient and duotone crossfades — prevents grey/muddy midpoints
- Shortest-path hue interpolation for smooth transitions
- **1.6x saturation boost** on final output to keep colors punchy
- Background color crossfades between duotone bg values

### Cycling

- Each duotone lasts ~30 seconds
- Smooth S-curve ease crossfade between pairs
- Full cycle: ~2.5 minutes through all 5 palettes

### Brightness

- **Elevation-driven**: `dim = 0.35 + val * 1.15`
  - Valleys (val=0): 35% brightness — dark, receding
  - Peaks (val=1): 150% — overdriven, vivid
- Minimum RGB floor: background color + 10
- Creates strong 3D depth perception

## Name Rendering

### Mask Generation

- Offscreen canvas renders "WORTHY" and "RAE" using system font (`Arial Black`, 900 weight)
- Font size: 18% of viewport height per line
- Text centered horizontally, two lines centered vertically
- Pixel data sampled as boolean mask (threshold > 128)

### Name Appearance

- Characters: same density ramp, elevation boosted (`val * 0.2 + 0.8`)
- Color: **pure white** with subtle pulse (`0.93 + 0.07 * sin(...)`)
- Font weight: **bold**
- Stands out clearly against colored terrain

## Grid Layout

- Font: JetBrains Mono / Courier New, monospace
- Font size: `max(5, min(9, viewportWidth / 180)) * devicePixelRatio`
- Cell width: `fontSize * 0.602`
- Cell height: `fontSize * 1.0`
- Noise scale: 0.015 (controls terrain feature size)
- Renders every cell every frame via `requestAnimationFrame`

## Performance

- Dense grid (~15,000-25,000 characters depending on viewport)
- All noise computed per-frame (no caching needed at this scale)
- Single canvas, no DOM character elements
- `fillText` per character — canvas batching handles this efficiently
- Target: 60fps on modern hardware, acceptable degradation on older devices

## Mobile

- Font scales down naturally via `min()` formula
- Fewer cells on smaller screens = less computation
- No mouse interaction in this design (pure visual)
- Name mask regenerated on resize
